# AGENTS.md

Інструкція для агентів, які працюють із цим репо (Codex, ChatGPT, Cursor та
інші). Claude Code читає те саме з `.claude/skills/videoworks/SKILL.md`.

videoworks — CLI для монтажу відео за текстом: транскрипт зі словами й
таймкодами, план монтажу в `edl.json`, рендер через ffmpeg, субтитри й переклад.
Агент монтує, читаючи текст, а не переглядаючи відео.

## Головне

**Повна інструкція — [`.claude/skills/videoworks/SKILL.md`](.claude/skills/videoworks/SKILL.md).
Прочитай її перед будь-якою роботою з відео.** Там порядок дій, формат
`edl.json`, переклад, субтитри, локальні сторінки й межі. Нижче — лише те, що
треба знати, щоб не нашкодити, поки її не прочитав.

## Оточення

- Windows, Python 3.12 через `uv`: `uv sync`, потім `uv run videoworks doctor`
  перевіряє ffmpeg, CUDA й моделі. Деталі — у [README.md](README.md).
- Усі команди: `.venv\Scripts\python -m videoworks.cli <команда>`
  (або `uv run videoworks <команда>`).
- `transcribe` на відеокарті NVIDIA йде в рази швидше; на процесорі годинне
  заняття розпізнаватиметься довго — попередь людину.

### macOS (Apple Silicon)

Проєкт писали й перевіряли на Windows з NVIDIA; на Mac його ще ніхто не
запускав, тож перший прогін — теж перевірка. Що відомо заздалегідь:

- Шляхи в інструкції віндові. На Mac замість `.venv\Scripts\python -m
  videoworks.cli` пиши `uv run videoworks` (або `.venv/bin/python -m
  videoworks.cli`).
- ffmpeg — з Homebrew: `brew install ffmpeg`. Потім `uv sync --extra mlx` і
  `uv run videoworks doctor`.
- Розпізнавання на Mac іде бекендом `mlx` (mlx-whisper на графічному чипі
  Apple), а не faster-whisper: той на Mac рахує лише процесором. `transcribe`
  обирає `mlx` сам, якщо поставлено `--extra mlx`. Модель та сама — `large-v3`,
  мовлення так само вирізається Silero VAD.
- `--encoder nvenc` на Mac немає; типовий `libx264` працює.
- Пілот звуку `soundtrack-test` розпізнає свої уривки ще faster-whisper, тобто
  процесором; уривки короткі, тож це терпимо.
- Відео з iPhone (HEVC) Safari й Chrome на Mac грають самі, тож для
  `strike` `--proxy` зазвичай не потрібен.

### Перший прогін на Mac — зробити й записати

Бекенд `mlx` написано на Windows і перевірено лише тестами з підміненою
моделлю: MLX на Windows не ставиться. Поки ці кроки не пройдено, він вважається
неперевіреним. Пройди їх на першому ж справжньому занятті, перш ніж монтувати:

1. `uv sync --extra mlx`, потім `uv run videoworks doctor` — у списку
   бекендів має бути `mlx`. Якщо `uv sync` падає — зупинись і перекажи помилку
   людині дослівно.
2. Розпізнати заняття: `uv run videoworks transcribe <project> --lang uk`.
   У першому рядку виводу має стояти `mlx · large-v3 · apple-gpu`. Перший запуск
   завантажує модель (~3 ГБ), це окремо від часу роботи.
3. Порівняти з faster-whisper на тому самому записі (займе довше — він на
   процесорі):
   `uv run videoworks transcribe <project> --lang uk --backend faster-whisper --out projects/<project>/transcript.cpu.json`
4. Записати в `projects/<project>/project.md`, розділом «Перший прогін mlx»:
   - час обох прогонів і тривалість запису;
   - кількість слів в обох транскриптах і скільки з них із `prob < 0.5`
     (`uv run videoworks show <project> --words` або прямо з JSON);
   - на 3–4 фразах: чи збігаються слова й таймкоди початку слів (розбіжність
     до ~0.2 с нормальна, більша — підозріла);
   - чи немає вигаданого тексту на ділянках, де лише музика.
5. Відкрити `uv run videoworks strike <project>` і переконатися, що слова
   підсвічуються вчасно під час відтворення — це найкраща перевірка таймкодів.
6. Якщо все гаразд — далі працювати з `transcript.raw.json` від `mlx`. Якщо
   слова чи таймкоди помітно гірші — повернутись до faster-whisper:
   `transcribe … --backend faster-whisper`, і сказати людині, що саме не так.

Якщо щось у коді треба виправити, правки — окремим комітом із поясненням,
що побачив на Mac.

## Проєкти й матеріали

- Один проєкт — одна папка `projects/<name>/`. Відео кладуть у
  `projects/<name>/media/`.
- **`projects/` не в git.** Відео, транскрипти, позначки, рендери живуть лише на
  цій машині. Не додавай їх у коміти й не видаляй — це матеріали людини.
- Почни роботу з проєктом із `projects/<name>/project.md` — памʼять попередніх
  сесій — і допиши туди, що зробив.

## Правила, які не можна порушувати

- **Покажи план і дочекайся згоди перед рендером.** `videoworks review
  <project>` друкує, що зникне, у словах. Не запускай `cut`, доки людина не
  підтвердила.
- **Не вигадуй таймкоди** — бери з `brief` або `transcript.raw.json`.
- **Не пиши команди ffmpeg в обхід CLI.** Чогось бракує — скажи людині.
- **Не редагуй руками** `transcript.cut.json` (він породжений з EDL) і
  `strikes.json` (там намір людини).

## Викреслювач: що вирізати з ефіру вирішує людина

`videoworks strike <project>` відкриває сторінку, де людина пензлем викреслює
слова, які не мають прозвучати. Позначки лягають у `projects/<name>/strikes.json`.

- Це інструмент для людини. Агент позначок не ставить і не знімає.
- Якщо відео на сторінці не грає (буває з HEVC із телефона) —
  `videoworks strike <project> --proxy`.
- **Звичайний рендер (`cut`) позначок не застосовує: викреслені слова в ньому
  прозвучать.** Перед рендером проєкту, де є `strikes.json`, скажи це людині
  прямо. Поки що глушить викреслене й підкладає чисту музику лише пілот
  `soundtrack-test`, на уривку до 3 хвилин.

## Розробка

- Тести: `uv run pytest -q`; логіка сторінки викреслювача —
  `node --test tests/strike_logic.test.mjs`.
- Код форматовано вручну: **не запускай `ruff format` на всьому дереві**, лише
  на нових файлах. `ruff check` має бути чистим.
- Коментарі, повідомлення й коміти — українською.
