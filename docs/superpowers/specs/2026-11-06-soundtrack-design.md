# Реконструкція звуку: сінк оригіналів треків і автомікс під голос

Статус: дизайн погоджено в чаті, чекає рецензії спеку. Ітерація 1 — «сінк + дакінг».

## Навіщо

Референсний кейс: відео заняття з аеробіки. Ведуча говорить **живим голосом у залі**,
без мікрофона; музика — плейлист зі Spotify через колонки зали; камера/телефон пише
все разом. Чистого фіду з пульта немає, але є файли оригіналів треків.

Мета — після транскрибації й монтажу додати шар, який за потреби **реконструює звук**:
кладе чисті треки, вирівняні до семпла, на кімнатний запис, а там, де ведуча говорить,
притишує музику й відкриває голос.

Що сказав користувач (зафіксовано):

- голос — живий у залі;
- фінальне відео — суцільне заняття, склейок мало;
- треки грають від початку до кінця, з кросфейдами Spotify;
- перша ітерація — сінк + дакінг, без віднімання треку з запису.

Критерії успіху ітерації 1:

1. На синтетичному стенді похибка сінку ≤ 1 мс, дрейфу ≤ 5 ppm, меж треку ≤ 0.25 с.
2. Дакінг ніколи не починається пізніше за перше слово фрази.
3. Повнота міток голосу ≥ 95% на стенді; слова пісень не викликають дакінгу.
4. Неоднозначність сінку на долю такту виявляється й показується, а не ховається.
5. Наявний пайплайн без `audio_source` працює байт-у-байт як раніше.

## Поза межами ітерації 1

- Віднімання відомого треку з запису (адаптивний фільтр, «ехоподавлення») для чистого
  голосу. Лишається гіпотезою на ітерацію 2: залишок дав би і кращий голос, і VAD.
- Пауза/перемотка треку посередині (шматкова розкладка одного треку на кілька
  розміщень). Модель її допускає, автодетекту немає.
- Зміна темпу.
- Шви музики по долях такту на склейках монтажу (суцільне заняття — швів мало).
- Доріжка звуку в `studio`. Правка — через `soundtrack.json` і `sync --nudge`.

## Місце в архітектурі

Шар працює на **сирому таймлайні**, до монтажу. EDL, перемапування й субтитри не
змінюються; реконструкцію можна перезібрати незалежно від монтажу.

```
transcript.raw.json ─┐
media/tracks/*.mp3 ──┼─ sync ──→ soundtrack.json (placements)
media/raw.mp4 ───────┘    │
                          ├─ voice ─→ soundtrack.json (voice)
                          └─ mix ───→ media/mix.wav  (+ out/sync-ab.wav)
                                          ↓
                    cut: EDL.audio_source = "media/mix.wav" → atrim з [1:a]
```

## Модулі

Пакет `src/videoworks/soundtrack/`:

| модуль | відповідальність | залежить від |
|---|---|---|
| `decode.py` | ffmpeg → mono/stereo float32 потрібної частоти, блоками | `ingest._binary` |
| `features.py` | огинаюча онсетів (мел-потік), GCC-PHAT, параболічна інтерполяція | numpy, scipy |
| `sync.py` | грубий + точний сінк, дрейф, межі, гучність → `Placement` | features, decode |
| `voice.py` | слова транскрипту мінус лірика → ділянки голосу; кандидати пропущеної мови | models, text |
| `mix.py` | огинаючі, ресемпл на `rate`, кросфейди, запис `mix.wav` і A/B | decode |
| `check.py` | preflight `soundtrack.json` | diagnostics |
| `bench.py` | синтетичний стенд із відомим еталоном і метриками | усе вище |

Нова залежність: `scipy` (FFT-кореляція, `resample`, фільтри). `librosa` не тягнемо.

## Контракт `soundtrack.json`

Моделі pydantic у `models.py`, поруч з `Edl`. Розширювати можна, перейменовувати — ні.

```jsonc
{
  "source": "media/raw.mp4",
  "placements": [
    { "track": "media/tracks/01.mp3",
      "track_sha256": "…",
      "track_in": 0.0, "track_out": 212.4,  // що з треку реально звучить
      "rec_at": 13.482,                     // де track_in у записі (з акустичною затримкою)
      "rate": 1.000021,                     // тривалість у записі = (out - in) * rate
      "gain_db": -3.1,                      // підгонка чистого треку під рівень у залі
      "confidence": 0.91,                   // головний пік / найбільший бічний
      "alternative": 0.444,                 // зсув другого піку, якщо він близький
      "sync_error_ms": 0.4,                 // розкид залишків прямої дрейфу
      "locked": false }                     // поправлено вручну — sync не перезаписує
  ],
  "voice": {
    "source": "transcript",
    "spans": [[41.20, 44.85]],
    "lyrics_dropped": 37,
    "suspects": [[102.1, 103.4]]            // надлишок енергії без слів — лише звіт
  },
  "mix": {
    "mode": "blend",                        // blend | room
    "duck_db": -12.0,
    "room_floor_db": -24.0,
    "preroll": 0.20, "hold": 0.60,
    "attack": 0.08, "release": 0.60,
    "room_band": [150, 6000]
  }
}
```

Кросфейд Spotify — два розміщення, що перекриваються за часом запису.

## Алгоритми

### Сінк

1. **Грубий.** Огинаюча онсетів (спектральний потік, ~40 мел-смуг, 100 кадрів/с,
   півхвильове випрямлення) для запису й кожного треку. FFT-крос-кореляція → пік →
   `rec_at` ±10 мс. Впевненість = головний пік / максимум поза ±50 мс. Якщо другий пік
   ≥ 0.8 головного — заповнюємо `alternative`: для аеробіки (130–140 BPM) це типово
   зсув на долю, ~0.44 с.
2. **Точний і дрейф.** Вікна 4 с кожні 10 с вздовж треку, 16 кГц. GCC-PHAT між вікном
   треку (зсунутим на грубий `rec_at`) і записом → затримка з параболічною
   інтерполяцією. Відкидаємо вікна з голосом і з низькою когерентністю. Theil–Sen
   `lag(t) = a + b·t` → `rec_at`, `rate = 1 + b`; розкид залишків → `sync_error_ms`.
3. **Межі.** Нормована кореляція по вікнах; де падає нижче порогу на краях — `track_in`
   / `track_out` (уточнення до 0.1 с меншими вікнами). Провал посередині — попередження
   «інша версія треку».
4. **Гучність.** `gain_db` = RMS запису / RMS вирівняного треку на вікнах без голосу.

### Голос

1. Слова з `transcript.raw.json`.
2. Кожен трек проганяється тим самим ASR; кеш `media/tracks/<name>.transcript.json`.
   Слова лірики переносяться в час запису через розміщення.
3. Слово транскрипту відкидається, якщо в ±0.3 с є слово лірики з нормованою схожістю
   тексту ≥ 0.6. Лише збіг за часом не відкидає — інакше губилась би мова поверх співу.
4. Слова з проміжком < `hold` зливаються в одну ділянку.
5. «Надлишок енергії»: спектр запису проти передбаченого з треку (посмугове
   підсилення, медіана) у 300–3400 Гц; ≥ 6 дБ понад передбачення без слів →
   `suspects`. У дакінг не йде.

### Мікс

- Чистий трек: 0 дБ поза голосом, `duck_db` у ділянці; косинусна рампа `attack`,
  що **закінчується** за `preroll` до першого слова; `release` після останнього.
- Кімната: режим `blend` — смуга `room_band`, рівень від `room_floor_db` до 0 дБ
  дзеркально до дакінгу; режим `room` — повна смуга, чистий трек у ділянці вимкнено.
- Там, де немає жодного розміщення, — кімната на 0 дБ повною смугою.
- Трек ресемплиться на `rate` цілком (FFT), потім кладеться в `rec_at` із `gain_db`;
  перекриття — рівнопотужний кросфейд.
- Обробка блоками по ~30 с (година на 48 кГц ≈ 700 МБ моно).
- Вихід: `media/mix.wav`, стерео 48 кГц 24 біт (трек — стерео, кімната — моно в центрі).
  `out/sync-ab.wav`: кімната зліва, вирівняний трек справа — розсинхрон чути одразу.

## Зміни в наявному коді

- `models.py`: `Soundtrack`, `Placement`, `VoiceInfo`, `MixSettings`;
  `Edl.audio_source: str | None = None`.
- `paths.Project`: `tracks`, `soundtrack`, `mix`, `sync_ab`.
- `render.build_filtergraph`: при `audio_source` — другий вхід, `atrim` з `[1:a]`,
  `afade` ~10 мс на кожному шві. Receipt хешує `audio_source`.
- `audio.py`: музичний профіль `AudioSettings` (без де-есера, мʼякший компресор),
  `cut` обирає його, якщо в EDL задано `audio_source` і профіль не перевизначено.
- `cli.py`: `sync`, `voice`, `mix`, `soundtrack-bench`; `sync --nudge <i> <секунди>`
  ставить `locked`.
- `SKILL.md`: крок «реконструкція звуку» — коли пропонувати, як читати звіт sync,
  що робити з `alternative` і `suspects`.

## Помилки й перевірки

Preflight `soundtrack.json`, fail-closed:

- error: розміщення поза межами запису; файл треку відсутній або хеш не збігається;
  `rate` поза 1 ± 500 ppm; перекриття > 15 с; параметри міксу поза межами.
- warning: `confidence` < 3; заповнений `alternative`; `sync_error_ms` > 2;
  провал кореляції посередині треку; є `suspects`.

`mix` не пише файл, якщо є error (угода `--force`, як в `apply`).

## Тестування

**Юніт:** GCC-PHAT на зсунутому шумі (суб-семпл), Theil–Sen на синтетичному дрейфі,
рампи огинаючої (кінець атаки ≤ першого слова), фільтр лірики, граф рендера з
`audio_source` і без (без — незмінний), preflight.

**Стенд** (`bench.py`): два синтетичні треки (бочка 132 BPM, акорди, неперіодичні
вставки) з кросфейдом 6 с + один суто періодичний трек; кімната — IR з RT60 0.8 с,
бас-шельф, затримка 23 мс, дрейф 30 ppm, шум −40 дБ, імітація AGC; голос — фрази TTS
або формантний шум. Звіт: похибки проти еталона й прохід/провал за критеріями успіху.

## Ризики

- **Періодичність біту** — хибний сінк на долю. Мітигація: `alternative` у звіті,
  `--nudge`.
- **AGC і шумодав телефона** — `gain_db` усереднений, музика в записі спотворена.
- **EQ / нормалізація Spotify** — гучність покриває `gain_db`, тембр не відновити.
- **Інша версія треку** — ловиться провалом кореляції.
- **Whisper пропускає тиху мову під музикою** — `suspects` у звіті; ітерація 2 —
  енергія залишку після віднімання треку.
- **Права:** чистий комерційний трек детектори Content ID ловлять упевненіше за
  кімнатний запис; файли треків — з легального джерела.
