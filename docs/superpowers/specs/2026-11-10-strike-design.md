# Викреслювач: позначити слова, які не йдуть в ефір

Статус: дизайн погоджено в чаті 2026-11-10, чекає рецензії спеку.

## Навіщо

Ведуча (Кріс) на записах занять іноді каже те, чого не хоче випускати. Їй треба
самій пройтись по запису й позначити ці місця — швидко, не відкриваючи монтажку
й не диктуючи таймкоди.

Що сказав користувач (зафіксовано):

- редактор показує відео, звук і місця, де вона говорить; є перехід
  «наступна / попередня фраза»;
- вона **буквально викреслює слова червоним пензликом зі смішним звуком**;
- у готовому відео на місці викресленого звучить **чиста музика з треку**,
  а не тиша й не вирізаний шматок;
- Кріс працює у **власній копії репо**, на своїй машині;
- UI має бути водночас приколом, який весело робити, і ергономічним софтом,
  що працює як треба.

Критерії успіху:

1. Заняття на 40 хвилин розмічається за один прохід без миші поза текстом:
   фраза звучить → мазок → наступна.
2. Те, що Кріс чує в редакторі як заглушене, — рівно ті відрізки, що підуть у
   рендер. Жодної другої копії правил на сторінці.
3. Позначка ніколи не зникає мовчки: ні через збій запису, ні через
   перезібраний транскрипт, ні через закриту вкладку.
4. Мовлення, якого ASR не розпізнав, теж можна викреслити.
5. Наявні команди й файли проєкту не змінюють поведінки.

## Поза межами

- **Застосування позначок на все заняття.** Це робить повний конвеєр
  `soundtrack`, якого ще немає (див. «Звʼязок із soundtrack»). Тут — редактор,
  файл позначок і перевірка наскрізь на короткому пілоті.
- Правка тексту транскрипту чи таймкодів слів.
- Викреслення картинки (блюр, вирізання кадрів).
- Доступ із мережі: сервер, як і `studio`, лише на 127.0.0.1.

## Місце в архітектурі

```
transcript.raw.json ─┐
media/<raw video> ───┼─ strike (сторінка) ──→ strikes.json
                     │                            │
                     │      (наступна задача)     ↓
                     └──────────── soundtrack voice/mix: на spans — лише чистий трек
```

Усе на **сирому таймлайні**, як і `soundtrack`: позначки не залежать від монтажу
й переживають зміну EDL.

## Контракт `strikes.json`

Лежить у `projects/<name>/strikes.json`. Модель pydantic `Strikes` у `models.py`.
Зберігає **намір** (що викреслила людина) і **похідне** (що глушити).

```jsonc
{
  "source": "media/aerobic #6.MOV",
  "transcript_sha256": "…",          // з якого транскрипту взято слова
  "pad": 0.15,
  "merge_gap": 0.25,
  "words": [                         // намір: викреслені слова
    { "w": "блін", "start": 412.31, "end": 412.62 }
  ],
  "manual": [                        // намір: відрізки без слів
    { "start": 955.10, "end": 957.40 }
  ],
  "spans": [                         // похідне: що глушити, для споживачів
    [412.16, 412.77], [954.95, 957.55]
  ]
}
```

Правила, усі в Python (`strikes.py`):

- **Слово ототожнюється часом і текстом, а не індексом** — індекс не переживає
  повторного ASR.
- **`spans`** = межі слова ± `pad`, ручні відрізки ± `pad`, обрізані до
  `[0, duration]`, сусіди з проміжком < `merge_gap` злиті. Перераховуються на
  кожен запис; споживачі читають лише їх.
- **`pad` = 0.15 с, а не 0.08, як у монтажі.** Замір у роадмапі дає медіанну
  похибку меж слів 154–223 мс. Для шва зайві 70 мс — це клац; для викреслення
  недобрані 70 мс — це почутий початок слова. Тут дешевша помилка — зʼїсти
  край сусіда.
- **Транскрипт змінився** (`transcript_sha256` не збігся): кожне викреслене
  слово шукаємо в новому за перетином у часі й схожістю тексту. Не знайшлось —
  стає ручним відрізком із тими самими межами. Позначка не губиться ніколи;
  сторінка показує, скільки слів «відклеїлось».
- Запис атомарний (тимчасовий файл + заміна), із відбитком проти затирання,
  як у `studio`.

## Модулі

| файл | відповідальність |
|---|---|
| `src/videoworks/strikes.py` | чиста логіка: фрази зі слів, `spans`, перенесення позначок на новий транскрипт, читання/запис. Без HTTP |
| `src/videoworks/strike_server.py` | обробник і `build_server`; бере `preview.send_video`, `preview.Server` і розбір тіла за зразком `studio` |
| `src/videoworks/web/strike/` | `index.html`, `app.js`, `brush.js`, `sound.js`, `style.css` — сторінка окремими файлами |
| `models.py` | `Strikes`, `StruckWord`, `ManualSpan` |
| `paths.py` | `Project.strikes` |
| `cli.py` | команда `strike` |

Сторінка — окремими файлами, а не рядком у `.py`, як у `studio`: там це вже
82 КБ в одному модулі, а тут інтерфейсу буде не менше. Файли їдуть у пакеті й
віддаються сервером із жорсткого білого списку імен.

### HTTP

- `GET /` і статичні файли сторінки
- `GET /state.json` → фрази зі словами, намір, `spans`, тривалість, відбиток
- `GET|HEAD /video` → відео з `Range`
- `POST /strikes` `{words, manual, stamp}` → запис; відповідь: нові `spans`,
  відбиток, лічильники. Відбиток не збігся → `moved`, нічого не записано.

### Фрази

Групує сервер: сегменти транскрипту, додатково розрізані на паузі > 0.6 с і на
стелі ~14 слів. Проміжки між фразами довші за 2 с віддаються як окремі
«музичні» рядки — у них живуть ручні позначки.

### Команда

`videoworks strike <project> [--port 8772] [--no-open]`

Без `transcript.raw.json` зі словами — зрозуміла відмова з підказкою
`transcribe`. Ctrl+C спиняє. Після зупинки друкує підсумок: скільки слів і
секунд викреслено.

## Інтерфейс

### Образ

**Коректурний аркуш.** Тепла паперова сторінка, текст фраз великим кеглем
чорнилом, поверх — жирний червоний пензель. Не «темна монтажка з панелями»:
Кріс не монтажер, і інструмент має виглядати як аркуш зі сценарієм, який вона
черкає. Усе, що не текст і не відео, — тихе й дрібне.

- Ліворуч, приклеєне до вікна — вертикальне відео на всю висоту.
- Праворуч — колонка фраз, що прокручується; активна фраза завжди на рівні
  очей (верхня третина), сусідні пригашені.
- Крайній правий край — тонка «мапа заняття»: уся тривалість згори донизу,
  червоні риски позначок, позиція головки. Клік — стрибок.
- Унизу — один рядок: відтворення, лічильник («викреслено 14 слів · 23 с»),
  стан збереження, звук пензля, довідка по клавішах.

Слова, в яких ASR не впевнений (`prob` < 0.5), — сірішим чорнилом: це
підказка «послухай уважніше», а не помилка.

### Пензель

- **Жест.** Натиснула на слові й повела — мазок тягнеться за вказівником і
  накриває кожне слово, якого торкнувся, включно з переходом на наступний рядок
  і в сусідню фразу. Pointer Events: миша, тачпад, палець, стилус.
- **Стирання тим самим жестом.** Якщо жест почався на викресленому слові —
  він стирає. Режим визначає перше слово, далі не міняється (як протягування
  по чекбоксах). Окремої гумки й перемикача немає.
- **Клік без руху** — перемотати на це слово. Мазком вважається рух понад
  6 px або перехід на інше слово; одне слово викреслюється коротким рухом
  по ньому.
- **Вигляд мазка.** SVG поверх тексту: смуга змінної товщини з рваними краями
  (зміщення шумом), трохи під кутом, із потовщенням на початку й сухим хвостом
  наприкінці. Форма залежить від зерна, привʼязаного до слова, — той самий
  мазок після перезавантаження виглядає так само й не «тремтить» при
  перемальовуванні. Суцільні сусідні слова в рядку — один довгий мазок, а не
  штрихи по слову. Текст під мазком лишається читабельним.
- **Дрібні бризки** на початку мазка, 300 мс. З `prefers-reduced-motion` —
  без них і без анімації наростання.

### Звук

Синтез через WebAudio, без файлів.

- Мазок — короткий «маркерний писк»: шум крізь смуговий фільтр + тон, що
  ковзає; висота залежить від швидкості руху й піднімається з кожним словом у
  жесті, тож довгий мазок звучить як глісандо.
- Стирання — мʼякий «чпок» зі спадом.
- Ціла фраза одним жестом — жирніший «шмяк».
- Звуки ≤ 150 мс, тихіші за відео, не накладаються стіною (обмеження
  голосів). Вимикач `M`, вибір запамʼятовується. Перший звук — лише після
  першого жесту користувача (вимога браузерів).

### Відтворення

- **Режим «по фразах» (типовий).** Фраза програється й спиняється в кінці.
  `Пробіл` — ще раз, `→` — наступна (і одразу грає), `←` — попередня.
- **Режим «підряд»** — звичайне відтворення; активна фраза їде за головкою.
- Слово під головкою підсвічується — видно, що саме зараз звучить.
- **Викреслене глушиться одразу в плеєрі**, за `spans` від сервера, з рампою
  ~30 мс. Після кожного мазка `spans` приходять у відповіді на запис — тобто
  чути рівно те, що отримає рендер, разом із запасом `pad`. Чистої музики в
  редакторі немає, там тиша; про це каже підказка.
- **«Перевірити викреслене»**: програє кожну позначку з 1.5 с контексту з
  обох боків, по черзі. Фінальний прохід перед тим, як закрити.

### Те, чого немає в тексті

- Тримаєш `B` (або кнопку з пензлем біля відео) під час відтворення — малюється
  ручна позначка від моменту натискання до відпускання, мінус 0.3 с на реакцію
  на початку.
- У колонці вона зʼявляється червоною плямою-рядком «♪ без слів · 2.3 с» на
  своєму місці в часі. Її можна стерти мазком, а краї посунути `[` `]` по
  0.1 с (із `Shift` — другий край).

### Ергономіка

| клавіша | дія |
|---|---|
| `Пробіл` | грати / повторити фразу |
| `←` `→` | попередня / наступна фраза |
| `X` | викреслити або відновити всю активну фразу |
| `B` (тримати) | ручна позначка під час відтворення |
| `Ctrl+Z` / `Ctrl+Shift+Z` | скасувати / повернути жест цілком |
| `N` / `Shift+N` | до наступної / попередньої позначки |
| `M` | звук пензля |
| `?` | довідка |

- **Скасування — жестами**, не словами: один мазок на десять слів знімається
  одним `Ctrl+Z`.
- **Збереження саме**, через ~0.5 с після жесту. У рядку внизу — «збережено»
  або причина. Якщо запис не вдався — стійка червона плашка, намір лежить у
  `localStorage` й досилається при відновленні; закриття вкладки з
  незбереженим питає підтвердження.
- **Файл змінили ззовні** (`moved`) — сторінка не затирає, а пропонує:
  перечитати або записати своє.
- Позиція (активна фраза) запамʼятовується — роботу можна кинути й
  продовжити з того ж місця.
- 40 хвилин — це кілька тисяч слів у DOM; малюється все одразу, SVG-мазки —
  лише для видимих фраз.

## Помилки

- Немає транскрипту / слів → команда відмовляє до запуску сервера.
- Відео не грає в браузері (HEVC у MOV) → сторінка показує причину й
  команду, якою зробити легку копію для перегляду. Перевіряється першим
  кроком реалізації на `aerobic-6`; якщо не грає — додається
  `strike --proxy`, що кладе H.264-копію в `out/strike-proxy.mp4`. Позначки
  в будь-якому разі в часі оригіналу.
- Тіло запиту з нескінченними чи відʼємними числами, `end < start`, за межами
  тривалості → 400, нічого не записано.

## Звʼязок із soundtrack

На викресленому звучить **зліпок музики з окремо викачаних треків** — той
самий вирівняний чистий трек, який `soundtrack` уже кладе поза голосом.
Викреслення — це ділянка, де кімнатний запис вимкнено повністю, а трек лишено
на повній гучності.

Стан на сьогодні: із плану `2026-11-06-soundtrack` реалізовано лише пілот
`soundtrack/trial.py` (`soundtrack-test`: один трек, до 180 с). Модулів `sync`,
`voice`, `mix` на все заняття ще немає.

### Що входить у цю задачу: пілот чує позначки

`run_trial` уже рахує `room_gain` і `music_gain` з кривої дакінгу. Додаємо
криву викреслення `strike` (0…1) з тих `spans`, що потрапили у вікно пілота:

- слова, що лежать у `spans`, вилучаються до `voice_spans` — на них музику
  не пригинаємо;
- `room_gain *= 1 − strike` — кімната **в нуль**, не на −24 дБ: на підкладці
  голос ще розбірний;
- `music_gain` тягнеться до 1 там, де `strike` = 1;
- рампи ~40 мс лежать **усередині** запасу `pad`, а не назовні;
- де трек не покриває відрізок — тиша, і рядок про це в `report.json`.

Так `soundtrack-test --start … --video` дає справжню перевірку на слух
наскрізь: Кріс викреслила → у пробі на цьому місці чиста музика. Без
`strikes.json` пілот працює байт-у-байт як раніше.

### Що лишається плану soundtrack

Те саме правило в повноцінних `voice` і `mix` на все заняття, із переходами
між треками. Коли їх буде реалізовано, вони читають `strikes.json` → `spans`
за цим контрактом; до плану soundtrack додається відповідний пункт.

## Тестування

**Юніт (`tests/test_strikes.py`):** `spans` — запас, злиття, обрізання по
краях запису; групування у фрази; перенесення позначок на змінений транскрипт
(знайшлось / стало ручним / нічого не загубилось — сума наміру зберігається);
кругова подорож запис → читання; атомарність запису.

**Пілот (`tests/test_soundtrack_trial.py` або наявний файл тестів пілота):**
крива викреслення — кімната в нулі всередині відрізка, рампи в межах запасу,
музика на повній; викреслені слова не дають дакінгу; без `strikes.json`
результат незмінний.

**Сервер (`tests/test_strike_server.py`, за зразком `test_studio.py`):** стан,
запис, відбиток і `moved`, 400 на сміття, статика лише з білого списку,
`Range` для відео.

**Сторінка:** прогін у браузері на `aerobic-6` — мазок через рядки, стирання,
скасування, глушіння на `spans`, відновлення після обриву сервера, клавіші.
Звук і «відчуття» оцінює людина.
