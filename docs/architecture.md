# Архітектура: агентна обробка відео

Чернетка. Мета — зафіксувати рішення, які вже випливають з ландшафту, і позначити
відкриті питання.

## Головний принцип: агент читає, а не дивиться

Відео як піксельний потік не влазить у контекст і коштує дорого. Тому шар розуміння —
текстовий, а візуальний підключається точково:

1. **Транскрипт із word-level таймкодами** — основна структура даних. ~12 КБ на проєкт
   (за замірами video-use). Усі рішення про різку приймаються тут.
2. **Сітка сцен** (PySceneDetect) — де кадр змінюється, куди не можна різати.
3. **Фільмстріпи на вимогу** — PNG-контактні аркуші лише для тих ділянок, де агенту
   реально треба побачити картинку (перевірити план, обрати обкладинку).

Різка завжди по межах слів — тоді шви не рвуть мову.

## Шари

```
┌─ Розуміння ────────────────────────────────────────────┐
│  ASR + вирівнювання + діаризація  →  transcript.json    │
│  детекція сцен                    →  scenes.json        │
│  фільмстріпи на вимогу            →  frames/*.png       │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─ Планування (LLM) ─────────────────────────────────────┐
│  розбір інтенту → план правок (EDL) → апрув користувача │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─ Виконання ────────────────────────────────────────────┐
│  EDL → FFmpeg-граф → preflight → рендер → receipt       │
│  або EDL → FCPXML для Resolve/Premiere/FCP              │
└─────────────────────────────────────────────────────────┘
```

## Рішення, які вже можна прийняти

**EDL як контракт між LLM і рендером.** Агент не пише команди FFmpeg — він видає
декларативний список правок (JSON): які сегменти лишити, де підписи, який колор.
Рендерер перетворює EDL на граф фільтрів. Це дає детермінізм, можливість передивитись
план до рендеру, undo і повторюваність.

**Preflight перед кожним рендером.** До запуску FFmpeg перевіряємо: сегменти не
виходять за межі, немає нульових тривалостей, аудіо-мікс не перевантажений, шрифти
для субтитрів існують. Fail-closed. Ідея з kinocut.

**Receipt на кожен вихідний файл.** Що з чого зроблено: вхідні файли + їх хеші,
EDL, версії тулів, команда. Без цього агентний монтаж неможливо ні відлагодити,
ні відтворити.

**Два виходи, не один.** Рендер у MP4 — для швидкого результату. FCPXML — для тих,
хто доведе руками в Resolve/Premiere. Другий вихід дешевий (auto-editor і buttercut
показують формат) і різко розширює аудиторію.

## Відкриті питання

- **Локально чи через API?** faster-whisper локально на GPU vs ElevenLabs Scribe
  (як у video-use). Локально — приватність і нуль вартості за хвилину; API — якість
  діаризації без возні з pyannote. Ймовірно, обидва за конфігом.
- **Форма інтеграції з агентом:** Claude Code skill (як video-use) чи MCP-сервер
  (як kinocut). Skill простіший і працює будь-де, де є shell; MCP дає типізовані
  тули й працює поза Claude Code. Схиляюсь до skill спочатку, MCP — коли API стабілізується.
- **UI.** Поки CLI. OpenCut як таймлайн — коли в них зʼявиться Editor API.
- **Українська мова.** Whisper large-v3 підтримує `uk`, але якість вирівнювання
  wav2vec2 для української треба заміряти окремо (див. [transcription.md](transcription.md)).
