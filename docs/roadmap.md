# Роадмап: від сирого відео до фінального файлу з субтитрами

Зафіксовані рішення: CLI + папка проєкту (без веб-UI), ASR локально на RTX 4060,
правка субтитрів через агента, не через власний редактор.

## Наскрізний потік

```
projects/<name>/
  media/raw.mp4
      │
      ├─ ingest ──────→ media/audio.wav (16 кГц моно), probe.json
      │
      ├─ transcribe ──→ transcript.raw.json      ← word-level, по СИРОМУ відео
      ├─ scenes ──────→ scenes.json              ← межі склейок
      │
      │   ┌─────────── АГЕНТ читає transcript.raw.json + scenes.json
      │   │            планує монтаж, показує план, чекає апрув
      │   └─────────→ edl.json
      │
      ├─ cut ─────────→ out/cut.mp4 + out/cut.receipt.json
      │                 transcript.cut.json      ← ПЕРЕМАПЛЕНІ таймкоди, не новий ASR
      │
      ├─ subtitle ────→ subs/uk.srt · uk.ass     ← розбивка на репліки
      ├─ translate ───→ subs/en.srt              ← LLM з контекстом усього тексту
      │   (агент править за інструкцією: терміни, довжина рядків, тон)
      │
      └─ burn ────────→ out/final.mp4            ← ffmpeg libass
                        out/final.softsubs.mkv   ← ті самі субтитри мʼяким треком
```

## Чому саме такий порядок

**Транскрипт робиться один раз, до монтажу.** Агент не може планувати різку, не маючи
тексту. Тому ASR — найперший крок, ще до будь-яких правок.

**Після різки таймкоди перемаплюються, а не транскрибуються заново.** Це головна
технічна ідея всього пайплайну. EDL знає, які інтервали сирого відео потрапили у
фінал і куди саме — значить, кожне слово можна перерахувати арифметично:

```
для слова w у transcript.raw:
    знайти сегмент EDL, що містить w.start
    якщо не знайдено → слово вирізане, викидаємо
    інакше → w.start_new = w.start - seg.src_in + seg.dst_out
```

Повторний ASR по змонтованому відео дав би інші слова, іншу пунктуацію і зруйнував
би звʼязок із рішеннями агента. Перемапування — детерміноване й миттєве.

**Субтитри генеруються з перемапленого транскрипту, а не редагуються після різки.**
Тому вони завжди синхронні за побудовою.

**Вжигання — останній і необовʼязковий крок.** Завжди зберігаємо ще й `.mkv` з
мʼякими треками: вижжене відео не можна ні перекласти, ні виправити.

## Контракти даних

Три файли, на яких тримається все. Їх схеми фіксуємо рано і не ламаємо.

**`transcript.json`** — слова з таймкодами, спікери, впевненість. Схема — у
[transcription.md](transcription.md).

**`edl.json`** — що агент вирішив зробити. Декларативно, без жодної команди ffmpeg:

```jsonc
{
  "source": "media/raw.mp4",
  "segments": [
    { "src_in": 12.44, "src_out": 48.10, "dst_out": 0.00 },
    { "src_in": 61.90, "src_out": 95.30, "dst_out": 35.66 }
  ],
  "overlays": [],
  "audio": { "normalize": "ebur128", "target_lufs": -16 }
}
```

**`receipt.json`** — провенанс кожного вихідного файлу: хеші входів, EDL, версії
ffmpeg і моделі, повна команда. Без цього агентний монтаж неможливо ні відлагодити,
ні відтворити. Ідея з kinocut.

## Етапи

### М0 · Фундамент — ✅ зроблено

- ffmpeg 9.0.1 (`libass`, `libx264`, `nvenc`), uv 0.12.10, CPython 3.12.14
- venv + залежності через `uv sync`, пакет `videoworks`, CLI на typer
- контракти `Transcript` / `Edl` / `Receipt` у `models.py` + тести
- `_cuda.py`: додає `site-packages/nvidia/*/bin` у шлях пошуку DLL — без цього
  CTranslate2 падає на першому forward
- `videoworks doctor`, `videoworks init <name>`

### М1 · Транскрипт — ✅ базово працює

- `ingest`: ffprobe → `probe.json`, витяг аудіо 16 кГц моно
- `ASRBackend` + реалізація на faster-whisper, автовибір `cuda/float16` ↔ `cpu/int8`
- Silero VAD увімкнений завжди — інакше галюцинації на музиці й тиші
- `transcript.raw.json` зі схемою і валідацією
- `videoworks transcribe <project> --lang uk`, `videoworks show <project> --words`

Лишилось: прогін на реальному українському відео і перевірка таймкодів очима.

### М2 · Субтитри — ✅ зроблено

- розбивка на репліки: паузи, межі речень, ліміт тривалості, стеля швидкості читання
- розкладка на рядки через DP: баланс довжин, шви на пунктуації, заборона лишати
  прийменник чи сполучник у кінці рядка (`ORPHANS`)
- експортери SRT / VTT / ASS через pysubs2, кегль відносно висоти кадру
- вжигання через `libass` + мʼякий трек у MKV
- `videoworks subtitle <project> --format srt,ass --burn --soft`

Два неочевидні моменти, знайдені на практиці:

**Бюджет символів ≠ можливість розкладки.** 63 символи влазять у 2×32, але якщо
жоден проміжок між словами не дає двох рядків по 32, репліку доводиться рвати на
три. Тому межу репліки визначає `fits_lines()` — здійсненність розкладки, а не
сумарна довжина.

**Сироту не лікують злиттям.** Коли остання репліка виходить на одне слово,
приліпити її до попередньої не можна — саме через це шов і виник. `_rebalance()`
натомість пересуває шов: забирає кілька слів у попередньої репліки, і жодна не
виглядає обрубком.

### М3 · Монтаж і перемапування — ✅ зроблено

- `edl.py`: побудова з інтервалів, preflight, `remap_transcript`
- **preflight** fail-closed: межі джерела, суцільність таймлайна призначення,
  розумність LUFS, попередження про сегменти коротші за кадр
- `render.py`: EDL → граф `trim`/`atrim` + `concat` → `cut.mp4` + `receipt.json`
- `fcpxml.py`: експорт у Resolve / Premiere / Final Cut
- `videoworks trim` (чорновий монтаж по паузах), `cut`, `fcpxml`

Знайдене на практиці:

**`-filter_complex_script` прибрано у ffmpeg 9.** Граф із сотень сегментів не
влазить у командний рядок Windows, тому передаємо його файлом — робоча форма
тепер `-/filter_complex <file>`.

**Тривалості кліпів у FCPXML — різниці зміщень, а не власні округлення.** Якщо
округлювати кожен сегмент незалежно, похибки накопичуються: 84+96+76 = 256 кадрів
проти 255 у секвенції, і останній кліп вилазить за межу.

**Транскрипт і відео мають бути з однієї стадії.** Перемаплені таймкоди поверх
сирого відео дають розсинхрон, тим більший, чим більше вирізано. `subtitle` тепер
сам обирає пару `transcript.cut.json` + `cut.mp4` або сиру.

**AAC додає ~100 мс у хвіст.** `cut.mp4` виходить трохи довшим за EDL: відео
покадрово точне (255 кадрів = 10.2 с), зайве — padding аудіо-енкодера. `start_time`
обох потоків нульовий, тож на синхронність це не впливає.

### М4 · Агентний шар — ✅ зроблено

- `.claude/skills/videoworks/SKILL.md` — інструкція агенту: порядок дій, формат
  EDL, обовʼязковий апрув перед рендером, межі («не вигадуй таймкоди», «не пиши
  команди ffmpeg»)
- `scenes.py` на PySceneDetect → `scenes.json`
- `brief.py`: `videoworks brief` — стисле зведення для контексту, `review` —
  що саме зникне, у словах
- `filmstrip.py`: контактний аркуш кадрів на вимогу
- `project.md` як памʼять сесії між запусками

Знайдене на практиці:

**Компактність — головне обмеження.** `transcript.raw.json` із таймкодом кожного
слова важить у рази більше за зведення, а рішення про різку приймаються на рівні
фраз. `brief` віддає саме фрази й сам звітує про свій розмір у символах.

**Підписи на контактному аркуші не варті мороки.** `drawtext` на Windows вимагає
шляху до файлу шрифту й екранування всередині фільтра. Замість цього команда
друкує таймкод кожної клітинки — агент співставляє сам.

**PySceneDetect на відео без склейок повертає порожній список.** Формально це
«немає переходів», але читається як помилка. Знаючи тривалість, віддаємо одну
суцільну сцену.

### М5 · Переклад і правка — ✅ зроблено

Перекладає агент — він і є мовною моделлю, окремий MT-рушій зайвий. Тул дає
круговий обмін і перевірку.

- `videoworks worksheet --to en --save` → аркуш із правилами, глосарієм і
  **бюджетом символів** на кожну репліку
- `videoworks apply --lang en` → підстановка в ті самі таймкоди, перерахунок
  розкладки, перевірка придатності
- `videoworks check --lang uk` → перевірка будь-яких готових субтитрів
- `glossary.tsv`: `термін<TAB>переклад`, порожній переклад = не перекладати

Знайдене на практиці:

**Бюджет символів — це min із двох різних обмежень.** Фізичного розміру
(рядки × символи) і швидкості читання (тривалість × CPS). На коротких репліках
діє швидкість, на довгих — розмір. Одне число замість двох правил.

**BOM тихо ламав глосарій.** Файл, збережений блокнотом чи PowerShell,
починається з U+FEFF, і перший термін ніколи не збігався. Скрізь, де читаємо
файли, редаговані людиною, тепер `utf-8-sig`.

**Записувати непридатний результат не можна.** Перша версія `apply` зберігала
субтитри попри помилки, затираючи робочу версію; помітилося б це вже на екрані.
Тепер запис лише після чистої перевірки, `--force` як свідомий виняток.

### М6 · Діаризація і якість — ⚠️ оснастка готова, замір чекає матеріалу

Зроблено:

- `metrics.py`: WER із вирівнюванням, точність меж слів (медіана / p90 / частка
  в межах 100 мс), узгодженість спікерів
- `benchmark.py` + `videoworks benchmark`: швидкість, WER, межі слів на одному
  матеріалі
- адаптери `whisperx_backend.py`, `moss_backend.py`, реєстр із перевіркою
  наявності; `doctor` показує, який бекенд встановлено
- `diarize.py`: перенесення спікерів на транскрипт із таймкодами слів

**Не зроблено: самого заміру на українській.** Потрібен реальний український
запис; синтетика з англійським TTS для WER не годиться.

Три висновки, які вже можна зафіксувати:

**Фонемна модель для української є.** У `DEFAULT_ALIGN_MODELS_HF` whisperX стоїть
`"uk": "Yehor/wav2vec2-xls-r-300m-uk-with-small-lm"` — перевірено в коді.
Ризик «alignment деградує до сегментного рівня» знято.

**MOSS не може бути основним бекендом.** Ні `TranscriptSegment`, ні
`SubtitleSegment` у його моделі не мають рівня слова — усе на рівні репліки.
Для монтажу по межах слів цього замало. Але як джерело діаризації без gated-ваг
pyannote він цінний: `diarize.assign_speakers` зшиває слова з faster-whisper і
спікерів із MOSS.

**Прогрів обов'язковий.** Перший замір показав `tiny` повільнішою за `small`:
у час потрапило завантаження ваг. `measure` тепер викликає `prepare()` до старту
секундоміра, а бекенди, які не вміють прогріватись, позначаються в таблиці `~`.

### Встановлення важких бекендів

Три пастки, кожна з яких мовчить замість того, щоб упасти:

**`torch` із PyPI під Windows — без CUDA.** Ставиться `2.14.0+cpu` (118 МБ проти
2.6 ГБ), `torch.cuda.is_available()` дає `False`, і все їде на процесорі. GPU-колеса
лежать на окремому індексі, який треба прописати в `[[tool.uv.index]]`.

**`tool.uv.sources` діє лише на прямі залежності.** torch приходить транзитивно
через whisperx і moss, тому маршрутизація на CUDA-індекс не спрацьовувала, поки
`torch` і `torchaudio` не назвали явно в самих екстрах.

**MOSS немає на PyPI** (404). Пакет ставиться з git, а hatchling блокує прямі
посилання, доки не виставиш `tool.hatch.metadata.allow-direct-references`.
Перевірка наявності теж була хибною: вона дивилась на `transformers`, який
прилітає як залежність інших речей і давав хибне «є».

**whisperx до 3.8.6 ламає основний пайплайн.** Він пінить `ctranslate2<4.5`, і
встановлення відкотило його 4.8.2 → 4.4.0. Той хоче cuDNN 8, тоді як torch тягне
cuDNN 9, і faster-whisper на GPU почав падати з `Could not locate
cudnn_ops_infer64_8.dll`. Помітилось лише тому, що я перепрогнав основний бекенд
після встановлення додаткового.

**whisperx і MOSS не уживаються на стабільних версіях.** 3.8.6 пінить
`huggingface-hub<1.0`, MOSS вимагає `transformers>=5.6`, який хоче
`huggingface-hub>=1.5`. Зафіксовано `whisperx==3.8.7rc1`, де пін послаблено —
свідомий компроміс замість розведення бекендів по різних venv.

### Перший замір (англійський TTS, 15 с — напрямок, не цифри)

| бекенд | ×RT | WER | медіана меж |
|---|---:|---:|---:|
| faster-whisper/small | 13.6× | 15.4% | 154 мс |
| faster-whisper/large-v3 | 12.3× | 7.7% | 223 мс |
| whisperx/small | 6.9× | 7.7% | — |
| whisperx/large-v3 | 6.0× | 0.0% | — |

Межі порівнювались із forced alignment whisperX як з еталоном — це не людська
розмітка, тож абсолютні числа умовні. Але **154–223 мс** удвічі перевищують поріг
у 100 мс, за яким шов уже чути. Для монтажу це аргумент за whisperX попри вдвічі
меншу швидкість; `transcribe --backend whisperx` тепер доступний як основний шлях.

Замір на українському матеріалі це не замінює.

## Стрес-тест на масштабі

17 хвилин синтетичного мовлення, 2149 слів, 18 склейок, 204 сегменти EDL.
Три речі, яких не було видно на 15-секундному кліпі.

**Граф фільтрів — 30 867 символів на 203 сегментах.** Ліміт командного рядка
Windows — 32 767. Тобто передача графа файлом (`-/filter_complex`) виявилась не
запобіжником, а необхідністю: 15-хвилинний запис уже впирається в межу.

**Змонтоване відео було довшим за план на 0.86 с.** ffmpeg округлює кожен
сегмент до кадру сам, похибки накопичуються, а таймкоди перемаплюються точною
арифметикою — субтитри поїхали б тим сильніше, чим далі від початку. Лікується
`edl.quantize()`: межі притягуються до сітки кадрів **до** рендеру й
перемапування. Після цього тривалість відео збігається з планом точно.
Розширюємо назовні, а не до найближчого кадру: інакше квантування зрізало б до
20 мс, тобто атаку приголосного. Ціна — близько 26 мс зайвого матеріалу
на сегмент.

**Whisper віддає слова з нульовою тривалістю** — від 1% до 5% залежно від
прогону, іноді кілька поспіль. Репліка, зібрана лише з таких слів, виходила
нульової тривалості й не з'являлась на екрані взагалі. Виправлено на двох
рівнях: `asr/repair.py` розносить вироджені послідовності по проміжку між
сусідами з відомим часом, а `subtitles` більше ніколи не віддає репліку
коротшу за `MIN_VISIBLE`. Пік швидкості читання впав із 400 до 38.6 симв/с.

**Що виявилось не проблемою.** `brief` на 17 хвилинах — 19.5 КБ проти 318 КБ
транскрипту, стиснення в 16 разів; на годину екстраполюється в ~67 КБ, що ще
прийнятно. Квадратичне вирівнювання в `metrics` — 1.4 с на 2149 слів, на
годинному записі буде ~25 с.

**Дефолтний поріг детекції сцен (27) пропускає мʼякі переходи.** На тестовому
відео з 18 склейками знайшлося 7; із порогом 8 — усі 18. На темному чи
низькоконтрастному матеріалі поріг треба знижувати.

## Ризики, які варто знати заздалегідь

**CUDA на Windows.** faster-whisper тягне cuDNN окремо від torch; типова помилка —
`Could not locate cudnn_ops64_9.dll`. Закладаємо час на це в М1 і документуємо
робочу комбінацію версій.

**8 ГБ VRAM.** `large-v3` у float16 займає близько 4.7 ГБ. Разом із діаризацією
може не влізти — тоді або послідовний прогін із вивантаженням моделі, або int8.

**Розбивка на репліки — не ASR-задача.** Саме вона відрізняє автосубтитри, які
виглядають дешево, від нормальних. На неї піде більше часу, ніж на сам ASR.

**Галюцинації на музиці й тиші.** VAD обовʼязковий, інакше Whisper вигадує текст
на музичних вставках.
